### 原始需求复述

用户原话：

> 「首页右上角+号里需要有扫一扫和面对面传文件，发起群聊里方式加入面对面输入相同数字建群，和从已有群聊建群，群聊和私聊均需要可以查看聊天记录，首页可以直接搜索聊天记录（做一个放大镜搜索图标在首页右上角+号左侧），通讯录里新的朋友可以看见添加好友的日期，好友的信息页面可以显示添加好友日期、共同群聊，可以设置朋友权限（参考微信包括朋友圈聊天拉黑等），群聊邀请可以通过二维码分享，和链接分享，在好友的信息页需要有把她（他）名片推送给好友，发现页面把我圈起来的去掉」

拆解为 10 项增量需求，详见第 5 节需求池。

## 2. 产品目标

1. **补齐「社交入口」完整度**：把扫一扫、面对面传文件、面对面/已有群建群等高频入口补齐，使首页「+」菜单和「发起群聊」覆盖微信同类的核心路径。
2. **强化「关系可见性」**：好友信息页补全添加日期、共同群聊、朋友权限（朋友圈/仅聊天/拉黑），并让朋友圈可见性真正受权限约束。
3. **提升「信息检索与分享」体验**：支持聊天记录查看与全文搜索，补齐群邀请二维码/链接分享，清理发现页冗余区块。

## 3. 用户故事

1. 作为普通用户，我希望在首页「+」菜单里直接找到「扫一扫」和「面对面传文件」，这样我能快速扫码加好友或和身边的人互传文件。
2. 作为群发起者，我希望能用「输入相同数字码」或「从已有群聊拉人」的方式建群，这样我不必逐个勾选好友也能快速组群。
3. 作为聊天用户，我希望在私聊和群聊里都能查看聊天记录并全文搜索，这样我能快速找回历史内容。
4. 作为用户，我希望在「新的朋友」和「好友信息页」看到添加好友日期、共同群聊，这样我能更了解这段关系。
5. 作为用户，我希望给某个好友设置朋友权限（不让他看朋友圈 / 不看他朋友圈 / 仅聊天 / 拉黑），这样我能控制隐私边界。
6. 作为群成员，我希望把群聊邀请做成二维码或链接分享给他人，这样对方扫码/点链接即可入群。

### 4.2 关键现状核对结论

- **好友关系表 `friendships` 已有 `created_at`**，可作为「添加好友日期」数据源；**好友申请表 `friend_requests` 已有 `created_at` 与 `updated_at`**，可区分「申请时间」与「通过/拒绝时间」。
- **二维码机制已有** `user_qr_tokens` 表 + `server/lib/qr.js` + `server/routes/qr.js`，当前仅服务于「用户名片二维码」，可扩展/复用到群邀请。
- **名片消息已有** 前端组件 `web/src/components/CardMessage.jsx` 与消息 `type = 'card'`（服务端回填 nickname/avatar_url）；好友信息页「分享名片」入口与 `ShareCardPicker.jsx` 已在 1.1.6 实现。
- **朋友圈已有** `moments / moment_likes / moment_comments` 表，可见性当前仅按「好友关系」实时判定（`lib/moments.js`），朋友权限需与该判定联动。
- **面对面配对（传文件 / 建群）当前无短码配对机制**，需新增「输入相同数字码」的配对交互与数据流，并可复用现有 socket.io 实时通道。
- **聊天记录分页能力已有**（消息按 `before_id` 游标分页，前端 `loadOlder` 上翻加载），但缺少「独立聊天记录查看入口」与「全文消息搜索」。
- **发现页**：`DiscoverPage.jsx` 中 `embedded` 分支（约第 73-88 行）渲染「头像 + 灰色小字签名（这个人很懒，什么都没写）」卡片，需移除；三项入口「扫一扫 / 朋友圈 / 我的表情」保留。

## 5. 需求池（P0 / P1 / P2）

### P0 —— 必须实现

#### 需求 1：首页右上角「+」菜单新增「扫一扫」与「面对面传文件」

- **涉及**：修改 `web/src/pages/ChatsPage.jsx`（移动端「+」菜单）；修改 `web/src/App.jsx`（桌面端 Sidebar「+」菜单）；复用 `web/src/pages/ScanPage.jsx`；新增「面对面传文件」页面与配对数据流。
- **现状**：移动端与桌面端「+」菜单目前仅含「发起群聊」「添加朋友」两项；`ScanPage` 已存在但仅从发现页入口进入。
- **验收标准**：
  - 首页右上角「+」菜单含 4 项：扫一扫、面对面传文件、发起群聊、添加朋友（顺序可自定义，扫一扫/面对面传文件在发起群聊之上）。
  - 点击「扫一扫」进入扫码页，可扫用户二维码并跳转用户资料页（行为与现有发现页入口一致）。
  - 点击「面对面传文件」进入配对页，可完成短码配对后传输文件。
  - 桌面端左栏「+」菜单与移动端保持一致。

#### 需求 2：发起群聊新增「面对面输入相同数字建群」与「从已有群聊建群」

- **涉及**：修改 `web/src/pages/GroupCreatePage.jsx`；新增「面对面数字码建群」「从已有群聊建群」交互与数据流；后端建群接口需支持上述两种新来源（成员来源与校验规则）。
- **现状**：`GroupCreatePage` 目前仅支持「好友多选」一种建群方式，后端建群要求成员必须是我的好友。
- **验收标准**：
  - 「发起群聊」页顶部提供建群方式切换：好友多选（默认）/ 面对面数字码 / 从已有群聊建群。
  - 面对面建群：≥2 名用户输入相同数字码后进入同一临时配对，确认后创建群；群人数需满足后端最低 3 人（含自己）约束。
  - 从已有群聊建群：列出「我的群聊」→ 选择某个群 → 展示其成员（可勾选）→ 确认后新建群，成员拉取自所选群。
  - 新建成功后进入新群会话；失败有明确 Toast 提示。

#### 需求 3：群聊与私聊均可查看聊天记录

- **涉及**：修改 `web/src/pages/ChatPage.jsx`（新增「查看聊天记录」入口）；新增聊天记录查看视图；复用现有消息分页能力。
- **现状**：聊天页可向上无限翻页加载历史，但无「查看聊天记录」独立入口，也无按日期/类型筛选。
- **验收标准**：
  - 单聊、群聊会话内均能进入「查看聊天记录」。
  - 聊天记录支持分页加载，按日期分组展示（复用现有时间格式化）。
  - （可选 P1）支持按消息类型（文本/图片/文件/名片/语音/视频）筛选。
  - 从聊天记录可定位并跳转回原会话上下文。
  - 查看聊天记录不应误触已读/未读状态（具体行为见待确认问题）。

#### 需求 4：首页搜索聊天记录（放大镜图标）

- **涉及**：修改 `web/src/pages/ChatsPage.jsx`（移动端顶栏「+」左侧新增放大镜）；新增消息搜索结果视图；后端新增「消息全文搜索」接口。
- **现状**：首页搜索当前仅按会话标题过滤；桌面左栏已有搜索框，移动端首页无搜索图标；无消息内容搜索能力。
- **验收标准**：
  - 移动端首页右上角「+」左侧有放大镜图标，点击进入消息搜索。
  - 输入关键词可搜索聊天消息**内容**（文本正文，并可扩展名片昵称、文件名等），不限于会话名。
  - 搜索结果按会话分组展示，点击可跳转至对应会话（尽量定位到命中消息）。
  - 搜索范围仅限我参与的会话；空结果有占位提示。

#### 需求 8：群聊邀请二维码分享 + 链接分享

- **涉及**：修改 `web/src/pages/GroupInfoPage.jsx`（新增邀请二维码/链接入口）；新增群邀请令牌与解析流程（可扩展复用现有 qr 机制）；新增扫码/打开链接入群流程。
- **现状**：`GroupInfoPage` 仅支持「邀请好友」多选；二维码仅支持用户名片；无群邀请码/链接。
- **验收标准**：
  - 群信息页可生成并展示「群邀请二维码」。
  - 可生成「群邀请链接」并复制/分享。
  - 他人扫群二维码或打开邀请链接后，可识别该群并加入（受群人数上限、群权限、是否已入群约束）。
  - 邀请码/链接可刷新；是否设有效期见待确认问题。

#### 需求 10：发现页移除「我的一句话」签名卡片

- **涉及**：删除 `web/src/pages/DiscoverPage.jsx` `embedded` 分支中的「头像 + 签名」卡片（约第 73-88 行）。
- **现状**：该卡片仅桌面左栏展示（`embedded`），移动端本就没有；三项入口「扫一扫 / 朋友圈 / 我的表情」正常。
- **验收标准**：
  - 发现页不再显示「头像 + 灰色小字签名」区块。
  - 「扫一扫 / 朋友圈 / 我的表情」三项入口仍正常显示与排序（按发现页配置）。
  - 桌面左栏与移动端发现页视觉趋于一致。

### P1 —— 应该实现

#### 需求 5：通讯录「新的朋友」显示添加好友日期

- **涉及**：修改 `web/src/pages/NewFriendsPage.jsx`；修改好友申请列表接口返回。
- **现状**：列表对已处理申请仅显示「已添加/已拒绝」，接口已返回 `created_at`（申请时间），但未返回「通过/拒绝时间」。
- **验收标准**：
  - 「新的朋友」列表中「已添加」条目显示添加日期（格式如 `YYYY/M/D` 或 `MM-DD`）。
  - （可选）「已拒绝」条目显示处理日期；待处理条目显示申请日期。
  - 日期数据源取「申请通过时间」而非「首次发起申请时间」（见待确认问题）。

#### 需求 6：好友信息页显示添加好友日期 + 共同群聊

- **涉及**：修改 `web/src/pages/UserInfoPage.jsx`；修改用户详情接口（`GET /users/:id`）返回。
- **现状**：好友态资料卡展示昵称/用户名/手机号/签名，另有「设置备注」「朋友圈」入口；接口未返回添加日期与共同群聊。
- **验收标准**：
  - 关系为「好友」时，资料卡展示「添加日期」（数据源 `friendships.created_at`）。
  - 展示「共同群聊」列表（我与对方共同所在的群），点击可进入对应群聊。
  - 无共同群聊时隐藏或显示「无共同群聊」；非好友关系不展示以上两项。

#### 需求 7：好友信息页可设置朋友权限（朋友圈 / 仅聊天 / 拉黑等）

- **涉及**：新增「朋友权限」数据（方向为「我对该好友」）；修改 `web/src/pages/UserInfoPage.jsx`（新增权限入口 + 设置弹层）；修改朋友圈可见性判定（`lib/moments.js` 联动）；修改单聊发送校验（拉黑联动）。
- **现状**：无朋友权限模型，朋友圈可见性仅按「是否好友」判定；无拉黑。
- **权限项（参考微信）**：
  1. 不让他（她）看我的朋友圈
  2. 不看他（她）的朋友圈
  3. 仅聊天（等价于 1 + 2 同时生效，双方朋友圈互不可见）
  4. 加入黑名单（拉黑）
- **验收标准**：
  - 好友信息页可进入「朋友权限」设置，4 项可独立/组合设置并可随时修改或取消。
  - 「不让他看我的朋友圈」生效后，对方时间线不再出现我的动态（服务端在对方视角过滤）。
  - 「不看他（她）的朋友圈」生效后，我的时间线不再出现对方动态。
  - 「仅聊天」= 双方朋友圈互不可见。
  - 「拉黑」生效后：对方无法向我发送消息；朋友圈双向不可见；具体是否解除/保留好友关系与会话见待确认问题。
  - 权限设置后朋友圈时间线立即/刷新后生效。

## 6. UI / 交互说明

### 6.1 首页「+」菜单（需求 1）

- 移动端与桌面端「+」菜单统一为列表式弹层，项顺序建议：**扫一扫 → 面对面传文件 → 发起群聊 → 添加朋友**。
- 「扫一扫」复用现有 `ScanPage`（摄像头扫码），进入后行为不变。
- 「面对面传文件」进入新配对页：默认展示「我的数字码 + 输入对方数字码」；配对成功后进入文件选择/发送界面。

### 6.2 发起群聊（需求 2）

- `GroupCreatePage` 顶部改为「建群方式」分段选择器：
  1. **选择好友**（默认，保留现有多选 + 群名输入）。
  2. **面对面建群**：展示一个短数字码（如 4 位），并允许输入相同数字码加入同一配对；配对成员确认后创建群。
  3. **从已有群聊建群**：展示「我的群聊」列表 → 选中后展示该群成员（勾选态）→ 确认建群。
- 三种方式最终都复用「创建群聊 → 进入新群会话」的收尾流程。

### 6.3 聊天记录查看（需求 3）

- 聊天页顶栏「···」菜单新增「查看聊天记录」。
- 记录页：按时间倒序分页，按日期分组；顶部可加消息类型筛选（P1 可选）。
- 点击某条记录可跳回会话（并尽量滚动定位）。

### 6.4 首页消息搜索（需求 4）

- 移动端首页顶栏「+」左侧新增放大镜图标；桌面端复用左栏已有搜索框，但搜索范围从「会话名」扩展到「消息内容」。
- 搜索结果页：按会话分组列出命中消息摘要（含发送者、时间、匹配片段），点击进入会话。

### 6.5 新的朋友 / 好友信息页（需求 5、6）

- 「新的朋友」：已处理条目在状态文案旁显示日期，采用弱化灰色小字。
- 「好友信息页」：在资料卡下方新增「添加日期」「共同群聊」信息区（或作为独立行）；共同群聊以列表行展示，可点击进入。

### 6.6 朋友权限（需求 7）

- 好友信息页好友态新增「朋友权限」入口（与「设置备注和标签」「朋友圈」同区块）。
- 权限设置弹层/页面含 4 个开关：
  - 不让他（她）看我的朋友圈
  - 不看他（她）的朋友圈
  - 仅聊天（打开时前两项联动置灰/开启）
  - 加入黑名单（危险操作，二次确认）
- 权限项即时保存并 Toast 反馈；拉黑需二次确认并明确后果提示。

### 6.7 群邀请（需求 8）
